二、确认的问题
1. 旧版用 thread-stream-following-changed 的最后一个订阅推断当前对话。实机发现一个客户端同时订阅 A、B，前台切换并不保证重新订阅，因此状态栏可能一直显示 A。
2. 状态栏 Speed 实际取 AverageTps（已完成响应的累计平均速度），不是短窗实时文本速度，长任务中自然变化很慢。
3. 旧版让 token_usage_record 和 token_count 两种累计记录按到达顺序互相覆盖。实机捕获了同一对话总量反复回落的现象；旧镜像会覆盖较新的官方累计记录。
4. 仅做时间平滑仍不能解决流式 BPE 重分词。新增反例：半个 function 单词先到，较久后补全，旧算法积分得到 2，而最终 token 数是 1，误差 100%。初轮随机测试没有发现这一问题，后续针对性测试发现并修正；不要把初轮通过当成充分证据。

三、现在怎样选择对话
- VisibleConversationResolver 从所贴附 Codex 窗口的 UI Automation RootWebArea 读取当前页面标题。
- 用 state_5.sqlite 的显示名称（name，空时回退 title）作精确唯一匹配，取得 thread ID。
- 重名、未知标题、新对话、读取失败都保持未识别；不使用最近活跃对话顶替。
- 手动锁定的对话继续优先；正常模式仅显示所选一个对话，不求多对话之和。
- 后台读取前后核对标题；切换窗口后丢弃旧窗口的异步结果。
- 切换对话清除旧速率保留状态；订阅变更串行协调；不接收已取消订阅对话的迟到输出。
- 详情标题和托盘会话项展示所选对话，便于人工对照。
限制：标题匹配是客户端兼容方案，不是官方当前标签页 API。同名对话会主动放弃匹配。应继续审查重名、改名、多窗口、标签页、远程对话及 UIA 元素失效场景。

四、实时测速数学定义
计数口径：o200k_base 对新增可见模型文本的估算；不是数据包数，不是官方所有输出 token。
采样桶宽 h=0.25 秒；平滑窗 W=2 秒（8 桶）。
令 d[j] 为第 j 桶提交的文本 token 增量：
  r[k] = sum(d[j], j=k-8...k-1) / 2
每秒的测量值不是随意抽一点，而是该秒四个 250ms 测量值的平均：
  v[n] = (r[4n-3] + r[4n-2] + r[4n-1] + r[4n]) / 4
因此每个已提交 token 对完整曲线面积贡献 1。积分必须包含输出停止后滤波器的尾部，并使用未四舍五入的 v[n]。
为了避免半个单词的分词变化，最后两个 o200k 正则预分词片段暂不计入；后续片段稳定或消息完成时结算。短答案、很长的无分隔词可能要等消息完成才有读数。这是有意延迟，不能用极小分母补偿。
快照是基线，不算新输出；同一文本修订不重复计数；断线、切换对话或丢失修订后重置测量基线。
显示每秒最多更新一次，并以一位小数呈现。无可用样本显示 --，不能拿响应均速替代。

五、等待保留、积分与均速不是一回事
- 工具调用或没有新增可见文本时，界面可保留上次速率，详情明确标注 last reading held。这是参考值，不代表仍在输出。
- 积分校验使用 VisibleTextWindow.ReadDisplayRate 的测量序列，包括滤波尾部；不能积分 LiveSpeedDisplay 无限保留的旧数值。显示四舍五入也不用于误差校验。
- 详情中的响应均速 = 可计时响应的官方 output_tokens 总和 / 相应客户端响应计时总和。该计数可能包括隐藏推理及工具参数，分母不含工具执行等待。
- 实时文本估算缺少隐藏推理等内容，不能要求它与官方全输出均速在 5% 内。5% 验收只适用于同一可见文本、相同 tokenizer、相同完整时间区间的积分一致性，不能解释成服务端实际 token 或任意瞬间速度误差保证。
- 服务器分批交付、客户端调度及稳定分词等待会改变短窗形状；守恒测试验证总量，不验证服务端每一个瞬间的解码速度。

十、0% 清透度按钮修复（glass.17）
原因：此前仅改变材质 TintAmount；该参数不是不透明度，底层仍采样原始背景，悬停还会单独减少染色。现在窗口和所有按钮共享同一份经过清透度处理的背景源：v=1-(1-c/100)^2。0% 时原背景贡献为零，100% 保留原背景；悬停染色调整在两个端点都归零。保留圆角覆盖、材质光照与交互动画。
新增渲染回归：明/暗主题 × 正常/悬停，纯黑和纯白背景在 0% 的窗口和两按钮采样像素完全相同；100% 仍有背景差异。累计自检 420 项通过。
隔离滑块性能：上下文滑块 3 秒 184 帧，绘制 P95 3.55ms；透明度滑块 3 秒 174 帧，绘制 P95 6.09ms，帧间隔 P95 20.71ms。应用渲染计数不等于硬件刷新率保证。
