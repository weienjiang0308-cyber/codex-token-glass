1. 此次最终行为
- 输出可见文本时，底部显示 Speed；命令、检索、工具、思考、就绪分别显示 Command / Searching / Using tools / Thinking / Ready。
- 不再用一串 --- 占位。没有已知用量的字段暂不显示，不伪造 0。恢复初期只有数据库总量时保留该已知总量，不用尚未到达的输入/输出明细算出假 0；缓存明细未知时不显示缓存率。
- 进入工具阶段后，上一有效文本速度以 Last 标注并排显示，也保存在详情；工具阶段和旧滤波尾部不会把保留值拖成 0 或 1。新文本到来后恢复更新。
- 详情平均速度仍是官方输出量与可计时响应时长的比值，与可见文本短窗估算分开。
- 对话识别独立于大日志读取，后台每 150ms 检查所贴附窗口的页面标题，UI 每 100ms 接收变化。切换时清掉旧对话显示，按 thread ID 缓存独立快照；迟到的旧页面结果不得覆盖新页面。
- 二级菜单为“全局上下文窗口”，修改根配置而非某个模型。当前对话报告的可用窗口仅供参考，不据此推断全局配置已经/尚未生效。未修改用户现有模型、容量或压缩阈值。
- 统计页名称是“API 等值”，提供按天、按对话、按每日对话汇总。仅在月度摘要保留“本月已薅 OpenAI … 的 API 等值”文案。
- 本月持续累计，过去月份归档到本机 JSON。已关闭且完整计价月份保留当时汇总，不随删除旧日志或新价格回写。

2. 发现并修复的真实问题
A. 订阅不等于前台选择：同一个 Codex 客户端可同时订阅多个对话，最后订阅者会错误抢选。现在按可见标题匹配唯一 ID；重名/未知页面显示未识别，不按最近活动猜测。
B. Speed 以前取累计平均，所以变化慢。现在实时与平均分离，并明确工作状态。
C. 滞后的 token_count 曾覆盖较新的 token_usage_record，累计数来回跳。现在存在新版正式累计记录时，以它为准；旧记录的上下文窗口信息仍可读取。
D. 仅平滑时间不能解决 BPE 重新分词。半个 function 补成完整单词的反例曾出现 100% 积分误差。现在保留末尾两个未稳定预分词片段，后续文字/消息完成后再结算。
E. 0% 端点曾误把 TintAmount 当不透明度，按钮还单独改变悬停染色。现在窗口和所有按钮共享一致背景混合，0% 原背景贡献为零。
F. 用户截图中的矩形接缝并非 E 的同一个问题。原生按钮重复背景/边框，以及裁切 DrawImage 的边界重采样仍产生接缝。取消原生背景/边框，改为与父窗同像素网格的 DrawImageUnscaled 后，实机按钮边界与底板对齐。

3. 测速数学和 5% 验收范围
使用 o200k_base 对新增可见文本估算；不是包数，也不是隐藏推理的官方总 token。
采样桶 h=0.25 秒；窗口 W=2 秒。
r[k] = sum(d[j], j=k-8...k-1)/2。
每秒展示的测量值 v[n] 为四个 250ms 测量值的平均，而非随意抽点。
完整测量曲线需包含输出停止后的滤波尾部。用未四舍五入、未保留旧值的 ReadDisplayRate 序列积分，逐项与同一文本的最终 tokenizer 计数对比。
禁止积分界面保留的旧读数；禁止将“可见文本估算”拿去与含隐藏推理/工具参数的官方 output_tokens 比较并宣称 5% 一致。
小答案、很长的无分隔单词可能等完成事件后才结算末尾，不用极短分母制造高速度。

6. 月度本地文件
%LOCALAPPDATA%\CodexStatusbar\monthly-api-equivalent.json
字段包括月份、Token、已知 API 等值、请求数、未计价请求数和是否已归档。按 UTC 分月。
API 等值只是按已知模型、缓存及上下文价格规则换算的参考价值，不是现金收入，也不是扣除订阅费后的净节省。
官方历史如果只有总 Token，没有模型/缓存明细，不凭空计算费用；费用汇总基于本机有明细的请求。未知价格保留未计价提示。
历史归档基于归档时可用的本机记录；已归档完整月份不会自动纳入以后导入的旧记录。跨设备完整账单核对不在本机估值范围内。

7. 给独立审查模型的重点
- 对话快速 A→B→A、未生成 ID、新标签页、同名/改名、多窗口、UIA 失效时，是否还有旧结果覆盖或误选。
- 原始 IPC 的 tool/status/完成时间是否覆盖不同工具类型；并行工具与文本输出时，状态优先级是否合理。
- BPE 稳定片段策略是否覆盖大小写、撇号、Unicode 组合字符、换行和 emoji；寻找反例，不要仅重复现有测试。
- 消息不追加替换、revision 缺口、快照重连及 262144 字符限制是否需要更明确的失效提示。
- 保留速度与可积分测量值不能混用，窗口尾部必须计入积分。
- 新旧累计载体切换、恢复与文件截断是否仍保持正确。
- 每日/对话汇总是否重复计入 fork 记录，月度归档冻结规则是否符合使用者预期。
- 原生按钮和材质缓存必须同时检查，不能再仅凭 shader 像素测试宣称整个窗口无接缝。
- 当前 GitHub Actions 的结果要核对对应提交，不要引用前一版成功运行。

一级弹出菜单正文从 10pt 调至 11pt，数值和统计按钮 11.5pt，统计按钮加粗。标签和数值按实际文字宽度分配间距；统计独立页面的标题/金额字号保持不变。

设置与统计面板不再同时叠着显示；打开设置时暂藏统计，关闭后恢复。
